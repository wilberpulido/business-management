# Etapa 1 — Pantallas del Dueño

## Contexto

La etapa 1 cubre el módulo de **Compras, Uso y Ventas** del sistema. El punto de partida es el rol `owner`, ya que tiene acceso global a todas las sucursales y debe poder realizar cualquier operación que un encargado o cajero pueda hacer, además de configurar toda la estructura del negocio.

La base de datos (21 tablas), los modelos Eloquent (20 modelos) y el sistema de roles/permisos están **100% implementados**. Todo el trabajo de esta etapa es de **interfaz**: componentes Livewire, rutas y vistas.

### Flujo general del dueño
1. Inicia sesión → entra en **modo global** (sin sucursal seleccionada).
2. En modo global puede gestionar la configuración del negocio, ver estadísticas y analíticas cruzadas entre sucursales.
3. Opcionalmente selecciona una **sucursal activa** para operar en ella.
4. Con sucursal seleccionada puede registrar inventario, ventas y gastos de esa sucursal.

### Dos modos de operación

| Modo | Sucursal activa | Qué habilita |
|---|---|---|
| **Global** | Ninguna | Dashboard, empresa, sucursales, usuarios, productos, combos, promociones, conversiones, analíticas |
| **Sucursal** | Una seleccionada | Todo lo anterior + inventario, ventas y gastos de esa sucursal |

---

## Convenciones

- **Estado**: `⬜ Pendiente` · `🔄 En progreso` · `✅ Completado`
- **Ruta base del dueño**: `/app/` (protegida por middleware `auth`)
- **Selección de sucursal activa**: guardada en sesión (`session('active_branch_id')`). `null` = modo global (estado válido, no de error).
- **Módulos globales** (sin sucursal requerida): M0, M1, M2, M3, M4, M5, M6, M7, M11
- **Módulos de sucursal** (requieren sucursal activa): M8, M9, M10

## Módulos

### M0 · Layout y Navegación `⬜ Pendiente`

Infraestructura de UI que todos los demás módulos dependen.

**Pantallas / Componentes:**
- Sidebar con navegación principal (colapsable en móvil). Los módulos M8, M9, M10 aparecen deshabilitados visualmente cuando no hay sucursal seleccionada.
- Header con: nombre del negocio, selector de sucursal activa, avatar + menú de usuario
- Selector de sucursal: dropdown con opción "Vista global" (sin sucursal) + lista de sucursales activas. Persiste en sesión.

**Acciones disponibles:**
- Cambiar a modo global (deseleccionar sucursal)
- Seleccionar una sucursal activa
- Navegar entre módulos

**Criterios de aceptación:**
- Al entrar por primera vez, el modo es global (sin sucursal seleccionada)
- Al cambiar de sucursal, todos los datos de la pantalla actual se actualizan
- Intentar acceder a M8/M9/M10 sin sucursal seleccionada redirige con un mensaje que indica que debe seleccionar una sucursal
- Si el dueño solo tiene una sucursal, el selector la muestra junto a la opción "Vista global"
- El layout es responsive (mobile-first) y soporta dark mode

### M1 · Configuración de Empresa `⬜ Pendiente`

El dueño ve y edita los datos de su empresa y configura las monedas que acepta.

**Pantallas:**
- `/app/empresa` — Página de configuración de empresa con dos tabs:
  - **Perfil**: editar datos generales (nombre comercial, RUC, dirección, teléfono, email, web)
  - **Monedas**: gestión de monedas activas (asociar/desasociar monedas del catálogo, marcar moneda por defecto)

**Acciones disponibles:**
- Editar datos de la empresa
- Agregar moneda al negocio
- Quitar moneda del negocio
- Marcar moneda como predeterminada

**Criterios de aceptación:**
- No se puede quitar la moneda predeterminada sin asignar otra primero
- Los cambios se guardan con feedback visual (toast de éxito/error)

---

### M2 · Gestión de Sucursales `⬜ Pendiente`

El dueño administra las sucursales de su empresa.

**Pantallas:**
- `/app/sucursales` — Listado de sucursales (nombre, dirección, estado activo/inactivo)
- Modal / panel lateral: Crear y editar sucursal

**Acciones disponibles:**
- Crear sucursal (nombre, dirección, teléfono)
- Editar datos de una sucursal
- Activar / desactivar sucursal

**Criterios de aceptación:**
- Una sucursal inactiva no aparece en el selector de sucursal activa del header
- No se puede desactivar la única sucursal activa

---

### M3 · Gestión de Usuarios `⬜ Pendiente`

El dueño invita usuarios y les asigna roles y sucursales.

**Pantallas:**
- `/app/usuarios` — Listado de usuarios del negocio (nombre, email, rol, sucursal(es) asignada(s), estado)
- Modal: Invitar / editar usuario

**Acciones disponibles:**
- Invitar usuario (nombre, email, rol: `branch_manager` o `cashier`, sucursal(es) asignada(s))
- Editar rol y sucursales de un usuario existente
- Desactivar / reactivar usuario

**Criterios de aceptación:**
- El `branch_manager` y `cashier` deben tener al menos una sucursal asignada
- El propio dueño no puede modificar su propio rol ni desactivarse

---

### M4 · Catálogo de Productos `⬜ Pendiente`

El dueño gestiona todos los productos del negocio (aplican a todas las sucursales).

**Pantallas:**
- `/app/productos` — Listado con filtros (tipo: materia prima / intermedio / terminado, estado activo)
- `/app/productos/crear` — Formulario de creación
- `/app/productos/{slug}` — Detalle / edición

**Acciones disponibles:**
- Crear producto (nombre, tipo, unidad de medida, moneda, precio base, descripción, maneja lotes sí/no)
- Editar datos generales del producto
- Cambiar precio base (genera entrada automática en `product_price_history`)
- Ver historial de precios
- Gestionar receta / BOM: agregar y quitar componentes (`product_compositions`) con cantidad y unidad
- Activar / desactivar producto (soft delete)

**Criterios de aceptación:**
- Solo los productos de tipo `finished` e `intermediate` pueden tener BOM
- Al cambiar el precio base se registra en historial con fecha y usuario
- Un producto con ventas registradas no puede eliminarse, solo desactivarse

---

### M5 · Conversiones de Unidades `⬜ Pendiente`

Permite definir conversiones custom entre unidades para un producto específico o de forma global.

**Pantallas:**
- `/app/conversiones` — Listado de conversiones (de · a · factor · producto asociado si aplica)
- Modal: Crear / editar conversión

**Acciones disponibles:**
- Crear conversión (unidad origen, unidad destino, factor, producto opcional)
- Editar factor de conversión
- Eliminar conversión

**Criterios de aceptación:**
- No se puede duplicar una conversión con la misma unidad origen/destino para el mismo producto (o global)

---

### M6 · Combos `⬜ Pendiente`

El dueño gestiona combos: grupos de productos con precio especial.

**Pantallas:**
- `/app/combos` — Listado con estado activo/inactivo
- Modal / panel lateral: Crear y editar combo

**Acciones disponibles:**
- Crear combo (nombre, moneda, precio especial, descripción)
- Agregar y quitar ítems del combo (producto, cantidad, unidad)
- Editar datos generales y precio
- Activar / desactivar combo

**Criterios de aceptación:**
- Un combo debe tener al menos un ítem para poder activarse
- El precio del combo puede ser menor o mayor que la suma de sus ítems (no hay restricción)

---

### M7 · Promociones `⬜ Pendiente`

El dueño configura descuentos automáticos aplicables a productos o combos.

**Pantallas:**
- `/app/promociones` — Listado con filtros (activa/inactiva, tipo de descuento)
- Modal / panel lateral: Crear y editar promoción

**Acciones disponibles:**
- Crear promoción (nombre, aplicable a producto o combo, tipo de descuento: porcentaje o monto fijo, valor)
- Configurar reglas de vigencia: rango de fechas, días de la semana, rango de horas (happy hour)
- Marcar como apilable o no apilable
- Activar / desactivar promoción

**Criterios de aceptación:**
- Si no se configuran reglas de tiempo, la promoción aplica siempre mientras esté activa
- Los días de la semana se almacenan como bitmask (ya implementado en el modelo)
- Solo una promoción no apilable puede aplicarse a la vez por ítem

---

### M8 · Inventario por Sucursal `⬜ Pendiente`

Vista y operaciones de inventario dentro de la sucursal activa seleccionada.

**Pantallas:**
- `/app/inventario` — Stock actual de la sucursal activa (producto, unidad, cantidad, lotes si aplica)
- `/app/inventario/ingresar` — Formulario de ingreso de mercancía
- `/app/inventario/movimientos` — Historial de movimientos (filtrable por tipo, producto, fecha)

**Acciones disponibles:**
- Ver stock actual filtrado por producto / categoría
- Registrar ingreso (`in`): producto, cantidad, unidad, costo unitario, lote opcional (número + vencimiento), notas
- Registrar ajuste manual (`adjustment`): producto, cantidad nueva o delta, motivo
- Registrar merma (`waste`): producto, cantidad, notas
- Ver detalle de cualquier movimiento

**Criterios de aceptación:**
- Al ingresar mercancía con lote, se crea o actualiza el `product_batch` correspondiente
- El stock en `inventories` se actualiza automáticamente al registrar cualquier movimiento
- Todos los movimientos quedan firmados con el usuario que los registró y la sucursal activa

---

### M9 · Ventas `⬜ Pendiente`

Registro de ventas desde la sucursal activa. Es la pantalla principal de operación diaria.

**Pantallas:**
- `/app/ventas` — Historial de ventas de la sucursal activa (fecha, total, estado, usuario)
- `/app/ventas/nueva` — Pantalla de punto de venta (POS)
- `/app/ventas/{id}` — Detalle de venta / opciones de anulación

**Acciones disponibles (pantalla de nueva venta):**
- Agregar producto al ticket (buscar por nombre, seleccionar cantidad y unidad)
- Agregar combo al ticket
- Por cada ítem, excluir componentes del BOM (ej: "sin cebolla")
- Aplicar descuento a nivel de venta (porcentaje o monto fijo)
- Ver promociones aplicables detectadas automáticamente
- Confirmar venta → descuenta inventario automáticamente (FEFO si hay lotes), registra movimientos `out`

**Acciones sobre ventas pasadas:**
- Ver detalle completo
- Anular venta (cambia status a `voided`, revierte stock)

**Criterios de aceptación:**
- Al confirmar la venta, se verifica stock suficiente; si falta, se muestra error específico por producto
- Los movimientos `out` del inventario quedan vinculados al `sale_item`
- Si hay lotes, el descuento sigue criterio FEFO (el que vence antes sale primero)
- Las promociones activas y aplicables se detectan automáticamente al momento de la venta

---

### M10 · Gastos `⬜ Pendiente`

Registro de gastos operativos por sucursal.

**Pantallas:**
- `/app/gastos` — Listado de gastos de la sucursal activa (fecha, nombre, monto, moneda)
- Modal: Crear / editar gasto

**Acciones disponibles:**
- Registrar gasto (nombre, monto, moneda, fecha, notas)
- Editar gasto
- Eliminar gasto

**Criterios de aceptación:**
- Solo gastos de la sucursal activa son visibles y editables desde esa sucursal
- El dueño puede ver gastos de cualquier sucursal cambiando la sucursal activa

---

### M11 · Dashboard `⬜ Pendiente`

Primera pantalla tras el login. Disponible en ambos modos; el alcance de los datos cambia según si hay sucursal seleccionada.

**Pantallas:**
- `/app/dashboard` — Panel principal

**Modo global (sin sucursal):**
- Ventas del día agregadas por sucursal (tabla comparativa)
- Gráfico de ventas de los últimos 7 días por sucursal
- Stock bajo a nivel empresa (productos críticos en cualquier sucursal)
- Comparativa de ingresos entre sucursales

**Modo sucursal (con sucursal seleccionada):**
- Resumen de ventas del día de esa sucursal (total, cantidad de transacciones)
- Stock bajo de esa sucursal
- Últimos movimientos de inventario
- Ventas recientes (últimas 5-10)
- Gráfico de ventas de los últimos 7 días

**Criterios de aceptación:**
- El dashboard detecta el modo actual y renderiza los widgets correspondientes sin recargar la página
- Los datos se cargan en tiempo real con Livewire

## Orden de desarrollo recomendado

```
M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9 → M10 → M11
```

El dashboard (M11) va al final porque depende de que existan datos reales de ventas e inventario para validar que funciona correctamente.
